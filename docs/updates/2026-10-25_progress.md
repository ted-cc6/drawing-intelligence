## 1. Where the system is

```
                ┌──────────────── REVIEW WORKFLOW (LangGraph, fixed path) ─────────────────┐
PDF ─► 1 Intake ─► 2 Understand ─► 3 Review (parallel reviewers) ─► 4 Verify ─► 5 Report
       code ✅       vision LLM ✅    code ✅ + 3 LLM reviewers ✅       code ✅      Excel + sheet ✅
                └──────────────────────────────────────────────────────────────────────────┘
Engineer ◄─► Q&A agent ✅ (di ask): tools over the saved results, every answer checked by code
```

The whole path runs end to end on one command, `di review drawing.pdf --export out/`, in about 2 minutes and
$0.04 per drawing. The Q&A agent answers questions about a reviewed drawing with cited, code-checked answers.

| Part | State | Where |
|---|---|---|
| Stage 1 (intake) | Text layer, title-block fields (incl. PARI's `#` notes block), general-tolerance table, stacked limits, symbols (GD&T frames from text, datum flags and finish marks from vectors) | `extraction/` |
| Stage 2 (understand) | `qwen3-vl-plus`, thinking off (ADR 0009) | `understanding/` |
| Rulebook | 174 draft rules: 110 code, 25 lookup, 39 LLM | `config/rules/`, [docs/rulebook](../rulebook/) |
| Code/lookup checks | **49 of 135 rules built** (44 check functions) | `review/checks/` |
| Reference tables | materials, DES-12 plating, IS 919 fits, IS 2102 general tolerances, ISO 261 / IS 4218 threads, each cited and structure-tested | `config/reference/` |
| LLM reviewers | `drawing_practice`, `manufacturability`, `design_intent` (`qwen3.8-max`); warnings only (ADR 0008); 15 of 39 LLM rules held back until their inputs exist | `review/llm_reviewer.py` |
| Verify | Drops any finding whose evidence does not resolve on the drawing | `review/verify.py` |
| Report | Excel checklist in PARI's columns + annotated sheet with zones | `report/` |
| Q&A agent | 8 read-only tools + a feedback log; citations and numbers checked by code (ADR 0011) | `qa/` |

## 2. Results

**Seeded set** (28 drawings with planted errors and clean near-misses, `di eval review`):
- Code checks: every planted error that has a built check is caught (18/18), **0 false alarms** on clean and
  near-miss drawings, precision 64/64. This is the CI gate.
- With the LLM reviewers: recall 19/22 of all planted errors; the LLM catch of P19 is not stable run to run.

**Held-out** (24 unseen client drawings, every finding labelled; `data/eval/heldout/2026-10-25/`):
- Code checks and lookups: **63 correct, 0 incorrect**, 9 unsure.
- LLM reviewers: 36% precision at first; **88% of decided findings** after three rounds of fixes (reading the
  `#` notes, holding back NM-008, narrowing MF-007 and WPS-004). These drawings guided the fixes, so 88% is
  optimistic until a fresh unseen set confirms it.
- Giving the LLM reviewers the stage-1 symbols lowered their precision (88% → 57%); those 8 rules also need to
  know which faces are functional, so they are held back again.

**Q&A agent** (`di eval qa`, 41 questions on 3 seeded and 3 held-out drawings; `data/eval/qa/results/`):
- `qwen3.8-max`: **40/41 pass, 41/41 verified**, no unverified numbers, all 8 guards (declines, not-in-the-data,
  feedback only when asked, a planted prompt-injection note ignored). $0.35 for the run.
- Reading every answer found three flaws the score had missed, all fixed: malformed citations accepted, an
  injection test that never reached the agent, and "not in the drawing's data" claimed without searching.

**Spend:** about $4.89 of the $8 budget (raised from $5 for the Q&A milestone). Every model reply is cached in
`data/cache/`, so re-running any evaluation above is free.

## 4. How to run the new parts

```bash
di review drawing.pdf --export out/          # full review; report in out/<drawing>/review_report.xlsx
di review drawing.pdf --no-understand        # code checks only, no model call
di ask drawing.pdf                           # chat about the reviewed drawing (empty line ends)
di ask drawing.pdf -q "Why is F3 flagged?"   # one question
di ask drawing.pdf --keep                    # keep the conversation; reopen with di ask --session <id>
di rules                                     # rulebook summary: which rules have a built check
di eval review --no-understand               # seeded set, code checks ($0)
di eval qa                                   # Q&A evaluation (asks before spending; cached re-runs are free)
```

Q&A limits per question (settings): 10 tool calls, 4 regenerations, $0.50. Engineers' verdicts on findings go to
`data/feedback/feedback.jsonl` (not committed).
